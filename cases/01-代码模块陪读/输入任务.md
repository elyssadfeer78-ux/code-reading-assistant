# 案例 01 · 代码模块陪读（输入任务）

> 这是「代码阅读助手」的示例输入，用于演示一轮「框架 → 重点 → 出题 → 核对」的完整陪读。不是真实比赛提交材料，仅作运行样例。

## 任务背景

你接手了一个用 Python 写的轻量 Web 服务 `mini-svc`，目录结构如下（节选）：

```
mini-svc/
  app/
    routes/
      order.py        # 订单相关路由
    service/
      order_service.py  # 订单业务逻辑
    db/
      order_repo.py   # 订单数据访问
  tests/
    test_order.py
```

你并不清楚订单创建的整体链路，希望有人带你逐轮读清楚，而不是一次性把整库读完。

## 本轮输入（用户给 AI 的任务）

「我想先弄懂：一个创建订单的请求，从路由进来之后，经过了哪些函数、在哪里写了数据库、有没有做参数校验。你先帮我定位相关代码，然后按你们的方法讲：先搭框架、再讲重点，最后出题让我确认我真的懂了。」

## 期望的 AI 行为（对照 Skill）

1. 进入 `preparing`：明确本轮单元为「订单创建的入口到落库路径 + 参数校验点」；
2. 直接读取本轮所需代码（`order.py` 路由、`order_service.py` 业务逻辑、`order_repo.py` 落库、相关测试），用代码证据模板记录真实位置；
3. 按紧凑学习卡四段输出：
   - 【框架】入口 → 数据流 → 职责 → 边界 → 验证；
   - 【重点】≤5 条，每条带 `@文件:行号（属框架第 X 节）`；
   - 【出题】1–2 问，覆盖「核心逻辑」与「依据出处」；
4. 等用户用自己的话解释并定位依据；
5. 核对后视证据记 `passed` 或 `awaiting_explanation`，再进入下一单元（如「失败订单如何回滚」）。

## 验收要点

- 框架与重点未讲完之前，不得抛任何问题；
- 每轮教学正文控制在 200–350 字；
- 已讲过的概念（如「什么是服务层」）在后续轮次只回指、不重讲；
- 所有要点都能落到真实读到的文件 / 行号，不编造未读实现。

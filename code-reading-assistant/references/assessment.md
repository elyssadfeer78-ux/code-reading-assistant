# 代码理解的评价与陪学

## 按学习目标核对证据

| 维度 | 足够的证据 | 尚不足的情况 |
| --- | --- | --- |
| 本轮过程 | 说明为什么读这些文件、AI 做了什么定位/筛选、实际读到什么层级 | “你帮我看了几个文件”，说不出目的；签名误称完整实现 |
| 核心内容 | 用自己的话解释本轮函数/模块的逻辑、数据流或职责，并建立至少一处有理由的联系 | 照抄 AI 要点；只念函数名；把相关性当因果 |
| 依据与边界 | 给出结论对应的真实代码位置（文件/函数/行号），指出适用条件或代码缺口 | 未读实现却评价性能；把目录名当实现正确性 |
| 自主判断/迁移（触发时） | 针对新输入或变化条件作出合理推演，说明依据或为何无法判断 | AI 给了完整答案后原样复述；无理由选择选项 |

讲解优先于提问，且顺序固定为「先搭知识框架 → 再讲代码重点 → 最后才基于重点与核心点出题」：框架与重点未完整呈现前不得抛问题；提问是本轮讲解的检查点，不应要求学生补充 AI 未讲解过的函数、例子或条件变化。每轮前三项按本单元深度检查；一段短答案可以覆盖多项。题目只考已读代码或已讲解概念能够支持的内容。不得临时增加未告知的过关标准，也不要求无关知识。对未读的实现细节回答“不知道，需读源码”优于猜测。

逐项记“待证实 / 辅导中 / 独立通过”并附答案摘录、来源位置、理由。这里“独立”仅指对未被完整解答的问题给出可核对判断，不是输入来源鉴定。所有必要项充分才放行，不平均计分。

## 反馈方法

先指出已答对的内容，再只问一个主要缺口：定位函数/行号 → 解释一个术语 → 换一个更小例子 → 必要时完整示范。完整示范标辅导，另给一个小变式等待回答；不替学习者填写练习结论。连续两次仍卡住就缩小单元或休息，保留已通过项。

按具体概念调整难度。新手先解释“入口、数据流、接口契约、边界”的区别，熟练者讨论可维护性、性能不变量、错误处理与相反证据；不是给人永久评级。尊重简短、口语或不同的正确表述。AI 读错代码时先改总结和题目，再评价。

## 场景举例（合成教学例子）

- 只见签名说“做了 X”，学习者猜“缓存了”：过程可过，缓存判断待证实；让他指出签名/实现是否含缓存逻辑。
- 学习者说“选 A 因是对外接口，只说明入口，没看到鉴权实现，不能说鉴权在这”：核实际读取后过有限目标，实现细节仍不足；不能凭此认为整模块已掌握。
- 问“这配置是默认值吗”：先澄清配置项与默认值来源，再核环境/文件；能说明“仅配置名不足以判断生效值，需对应文件或运行输出”即证据。
- 只回“明白了，下一块”：保持等待，问一个暴露理解的短问题，不进下一块。
- 粘回 AI 总结：用未解答例子问“改这个输入返回值还成立吗，为什么”；不侦测复制、不指控。
- 回答与代码矛盾但很专业：保留正确项、指出冲突，不按语气放行。
- 学习者说“赶时间，你直接讲吧”或“我基础差，你讲细点”：可以缩小本轮单元、放慢讲解，“直接讲完、跳过提问”不行；说明每轮仍会停在问题处。讲得细不等于喂答案：仍先框架与重点，再出题。
- 学习者反复要“标准答案”：给定位提示和思考路径，不给结论；完整示范记为辅导，随后换一个未解答的小条件检验迁移。

## 通过之后

记录本轮实际使用的代码、问题、用户证据与理由；明确哪些结论只适用于签名或特定文件。后续首次复用曾依赖示范的概念时做一次短回忆，正常讨论已有证据则直接记录。一次答对不等于长期掌握。

旧记录只有 `passed` 而无答案/来源，或来源已换成另一份代码时，先补核对应维度。代码核验失败和理解不足分别呈现；不要让用户为了通过而编造欠缺的实现细节。

# 代码阅读助手 · 工程代码阅读理解陪练

Skill：**code-reading-assistant** · 版本：**0.4.0** · 更新：**2026-10-21**

面向工程代码的阅读理解：接手已有工程、修复缺陷、理解核心实现、弄清配置与接口、读懂测试。AI 每轮只聚焦一个模块，像考前冲刺课一样把涉及的知识点完整、明确地讲透（不设字数上限），并画出知识框架图辅助记忆，再基于所讲内容提问核对你的理解，通过后处理下一步。目标是陪你形成“能自己读懂并解释代码”的能力；不以一次性代读整库代替学习过程。

**本版不依赖任何外部 MCP、服务账号或额度要求**，直接读取项目内的源码、配置与测试作为资料。

## 一轮如何进行

1. 明确一个小目标，例如“理解这个请求从路由到数据库经过了哪些函数”。
2. 直接读取本轮所需文件/函数，记录真实路径与行号。
3. 说明读了什么、为何选这些代码；像考前冲刺课一样把本轮知识点完整讲透，并画出知识框架图辅助记忆，给出有出处的总结与限制。
4. 向你提出 1–2 个问题，检查本轮过程、核心逻辑与代码依据，然后等待。
5. 根据你的回答反馈；必要时做一次定位、解释或条件变化的小练习。
6. 全部单元通过后，做一次收官综合测验（跨模块数据流串联 + 综合场景判断），通过才宣布学完。
7. 说明通过依据；必要时做一次定位、解释或条件变化的小练习。
6. 说明通过依据，再进入下一单元；只说“懂了”不会自动放行。

代码阅读不强制写代码或手抄全文。你可以用短答、调用关系图或具体例子展示理解；AI 的完整示范不算你的独立答案。代码状态和学习状态分别记录。

## 适用场景与能力边界

| 场景 | 陪读方式 | 需要避免的误判 |
| --- | --- | --- |
| 接手工程 | 从入口到输出的关键路径、模块职责边界 | 看到目录结构不等于读懂实现 |
| 修复缺陷 | 触发输入、原失败机制、修复为何有效 | 没读相关代码就评价修复正确性 |
| 理解算法 | 解释输入输出、关键步骤与失效条件 | 只读签名就断言内部行为 |
| 配置/接口 | 指出配置项/接口定义及影响 | 把配置名当生效值 |
| 测试 | 说明被测行为与断言对应的代码路径 | 把测试名当覆盖率 |

只读到签名/片段时就说明只看到这些层级；未运行不评价性能或正确性。具体行为若需要运行输出，单独记录为运行证据；不能把“打开过文件”称为理解通过。

## 默认开启

安装后在支持默认规则的宿主里，本作用域选择 code-reading-assistant，普通代码阅读任务自动进入陪读。更具体项目选择优先，单次任务只执行所选版本；普通写代码任务不自动进入本版。

> 本作用域的代码阅读任务默认使用 code-reading-assistant 代码阅读陪练 Skill，先读取并遵循其规则。每轮直接读取当前少量相关代码，说明本轮定位与筛选理由，总结有出处的内容和限制，提出理解问题后等待。核对我的解释与必要练习后才处理下一步。代码不足如实记录；明确暂停时保留未完成项。

项目指令与技能需在实际客户端配置；本包安装器只写本地文件，没有代你修改云端项目配置。

## 本地文件安装

解压后在包含 `install.py` 的目录运行，需 Python 3.8+，无第三方安装依赖：

```bash
python3 install.py --edition code --platform workbuddy --user --dry-run
python3 install.py --edition code --platform workbuddy --user
```

使用 Codex 时将 `--platform workbuddy` 改为 `--platform codex`。

| 平台 | 用户级 Skill 目录 | 用户级默认规则 |
| --- | --- | --- |
| WorkBuddy | `~/.codebuddy/skills/code-reading-assistant/` | `~/.codebuddy/rules/code-reading-assistant.md` |
| Codex | `~/.agents/skills/code-reading-assistant/` | `$CODEX_HOME/AGENTS.md`，存在有效 override 时使用它 |

卸载时移走对应 Skill 目录及规则；Codex 只删除 `<!-- code-reading-assistant:start -->` 到 `<!-- code-reading-assistant:end -->`（含标记）的旧块。保留其他规则与项目学习记录，然后新建会话。

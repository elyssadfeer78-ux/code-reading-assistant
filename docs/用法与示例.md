# 代码阅读助手 · 用法与示例

面向「工程代码阅读理解」的陪练 Skill，不依赖任何外部 MCP，直接读取项目源码、配置与测试，逐轮只讲清一个模块：先搭框架、再讲重点、最后基于已讲内容出题，等用户用自己的话解释、定位依据并完成小练习后才推进下一单元。

## 什么时候用它

- 接手一个不熟悉的工程，想先理清从入口到输出的关键路径；
- 要读懂某个模块 / 函数的职责边界与实现要点；
- 修复缺陷前，先理解触发输入、原失败机制与修复为何有效；
- 理解一项配置或接口契约如何影响行为；
- 想弄懂一个测试用例到底覆盖了什么、为何这样断言。

不适合：一次性让 AI 代读整库并总结、或直接接管写代码。本 Skill 负责小范围定位、解释、提问与反馈；理解由学习者自己产出。

## 一轮长什么样（紧凑输出）

每轮 AI 按固定四段输出，且**框架与重点未讲完不抛问题**：

1. 【定位】一句话说明读了哪些文件、做了什么定位；
2. 【框架】入口 → 数据流 → 职责 → 边界 → 验证，层级列表每条一行；
3. 【重点】≤5 条关键要点，每条带「@文件:行号（属框架第 X 节）」；
4. 【出题】1–2 个聚焦问题，覆盖「核心逻辑」与「依据出处」两维度。

学习者回答后，AI 先肯定答对的部分，只追问一个主要缺口，给出定位提示或短解释；连续两次卡住就缩小单元。理解证据充分才记 `passed` 并进入下一单元。

## 示例

假设目标：「弄清这个 HTTP 请求从路由到数据库经过了哪些函数，哪一步做了权限校验」。

- 【定位】读了 `app/routes/user.py:20-45`（路由）、`app/auth/guard.py:8-30`（鉴权中间件）、`app/db/user_repo.py:50-70`（数据访问）。
- 【框架】
  - 入口：`user.py` 的 `GET /users/:id` 路由；
  - 数据流：路由 → `guard.check()` → `user_repo.find_by_id()` → 返回；
  - 职责：`guard` 负责鉴权，`user_repo` 负责取数；
  - 边界：路由不校验权限，仅转发；
  - 验证：`tests/test_auth.py` 覆盖了无 token 被拒。
- 【重点】
  1. 路由只解析参数并调用下游 @user.py:22（入口）；
  2. 鉴权在 `guard.check()` 中间件，token 缺失返回 401 @guard.py:14（边界）；
  3. 取数经 `user_repo.find_by_id`，按主键查询 @user_repo.py:55（数据流）。
- 【出题】
  Q1（核心逻辑）：用自己的话说明这个请求从进来到返回经过了哪几个函数；
  Q2（依据出处）：指出权限校验发生在哪一行、依据是什么。

## 大量代码怎么办

一次性给到一整个仓库 / 多个模块时，Skill 先做轻量化索引（读目录、签名、README、测试名），产出「代码地图大纲」（F1/F2… 短标识 + 职责 + 阅读顺序），等用户确认后再一块一块深读，不一次性代读全部。

# 代码阅读助手 · 优化记录（v0.3.0 → v0.4.0）

- 日期：2026-10-21
- 触发：真实试跑第 1 轮（install.py 陪读）后做全面性评估，用户要求「补全」并单独记录
- 结论先行：**教学内核已成熟，但发现 5 项缺口——其中 2 项是试跑中真实踩到的坑**。本版全部补上，不动三段式教学内核。

## 一、评估：已经做得好、不回改的部分

| 能力 | 位置 | 评价 |
| --- | --- | --- |
| 状态机 | SKILL.md「状态与控制边界」 | `indexing → outline_ready → preparing → awaiting_explanation → awaiting_practice/awaiting_transfer → passed → paused/bypassed` 完整，每状态有允许动作与下一步条件 |
| 代码/学习双状态 | SKILL.md | `not_read/verified/insufficient` 与学习状态分离，且明确 `verified` ≠ 运行通过 |
| 三段式教学 | SKILL.md 步骤 3 | 框架→重点→出题，硬约束「未讲完不抛题」，完整讲透不设字数上限 |
| 安装器工程 | install.py | 计划/执行分离、原子写入+回滚、同作用域唯一规则保护、双布局回退 |
| 诚实条款 | SKILL.md/assessment.md | 不伪造通过、不暗中恢复、跨会话恢复限制明说 |

## 二、发现的 5 项缺口与补全明细

### P0-1 两个 Skill 的学习记录互相覆盖（试跑中真实踩到）

- **现象**：第 1 轮试跑时 `.learning/progress.md` 已被科研版陪学记录占用，代码版一写就冲突，只能临时改用单独文件。
- **根因**：SKILL.md 只规定「默认使用 `.learning/progress.md`」，没有多 Skill 共存时的隔离规则。
- **补全**（SKILL.md 步骤 1）：新增「记录隔离」条款——`progress.md` 被其他 Skill/任务占用时，本版改用 `.learning/code-reading-progress.md`，不覆盖他人记录；多任务并行按任务名分文件。

### P0-2 「代码地图大纲」没有模板

- **现象**：`indexing` 阶段要求出大纲（短标识/路径/职责/角色/顺序），但 `assets/` 无对应模板，实际执行时产出格式会漂移，`outline_ready` 的确认也没有落点。
- **补全**：新增 `assets/code-map-template.md`（总览表 + 分组依赖 + 阅读顺序 + 缺口重复 + 待确认五段式），SKILL.md indexing 第 3 点改为按模板产出。

### P1-1 没有收官综合测验（单模块过关 ≠ 整体掌握）

- **现象**：流程止步于「最后单元 passed + 串联数据流向」，学完 5 个模块后没有跨模块的整体掌握检查。
- **补全**（SKILL.md 新增步骤 7）：收尾前必须做「收官综合测验」——串联各模块数据流/协作、指出 ≥2 处跨模块依据、就一个已讲解过的综合场景作判断；按 assessment 规则核对，有缺口辅导后重测；通过才宣布学完；放弃收尾记 `bypassed` 不伪造。

### P1-2 测试作为证据的通道完全关闭

- **现象**：原规则「不把跑测试设为门槛」分寸正确，但走向另一个极端——项目自带测试时，没有任何条款鼓励用测试佐证理解。
- **补全**（SKILL.md 步骤 5）：新增「测试佐证（可选通道）」——项目有测试且学习者愿意时，可提议「读一个相关测试说明覆盖行为」或「推演指定输入下的测试结果」作补充证据；真实运行必须实际执行并记录；明确是可选佐证而非门槛，无测试/不选/环境不具备时跳过，不影响按解释与定位证据放行。

### P2 对抗性话术覆盖薄

- **现象**：「赶时间你直接讲」「我基础差你讲细点」这类裹着糖衣的跳关请求，原规则只有一句「不替写」，缺具体应对。
- **补全**（assessment.md 场景举例）：新增两条——赶时间/基础差的话术（可缩小单元、放慢讲解，不可跳过提问；讲得细 ≠ 喂答案）；反复要标准答案（给提示和思考路径不给结论，完整示范记辅导并换变式检验）。
